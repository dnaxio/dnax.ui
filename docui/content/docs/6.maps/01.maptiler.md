`provider="maptiler"` is the default: the map is fed by **MapTiler Cloud** through the
MapTiler SDK JS — vector styles, satellite imagery, 3D terrain — and it needs an **API
key**. Without one, `<q-map>` falls back to
[OpenStreetMap](/docs/maps/openstreetmap).

## API key

Create a free key (100 000 map loads per month, no card) at
[cloud.maptiler.com](https://cloud.maptiler.com/account/keys/), then hand it once to the
whole app:

```vue
<q-config-provider :component-props="{ QMap: { apiKey: 'YOUR_MAPTILER_KEY' } }">
  <q-map :provider="'maptiler'" center="[2.35, 48.85]" :zoom="12" />
</q-config-provider>
```

`provider="maptiler"` is the default, so it can be left out — writing it makes the
provider explicit, which is handy next to a
[`openstreetmap`](/docs/maps/openstreetmap) map in the same app.

…or per map with `api-key="…"`. A MapTiler key is **public by design** — it travels with
every tile request, so it ends up in your client bundle either way: restrict it to your
domains in the MapTiler console instead of trying to hide it. A common setup in Nuxt is
an environment variable read into `runtimeConfig.public` (this documentation site uses
`NUXT_PUBLIC_MAPTILER_API_KEY`).

Usage is counted **per session**: a map load, then any pan / zoom / tilt is the same
session. Geocoding, static maps and elevation have their own quotas
([sessions vs requests](https://docs.maptiler.com/sdk-js/cloud/sessions/)).

## Styles

`map-style` takes a shorthand name, which dnax.ui resolves to the SDK's `MapStyle`:

| `map-style` | MapTiler style | Other variants (`.DARK`, …) |
| --- | --- | --- |
| `streets` *(default)* | streets-v2 | DARK, LIGHT, PASTEL |
| `basic` | basic-v2 | DARK, LIGHT |
| `bright` | bright-v2 | DARK, LIGHT, PASTEL |
| `dataviz` | dataviz | DARK, LIGHT |
| `backdrop` | backdrop | DARK, LIGHT |
| `stage` | stage | DARK, LIGHT |
| `outdoor` | outdoor-v2 | DARK |
| `winter` | winter-v2 | DARK |
| `topo` | topo-v2 | SHINY, PASTEL, TOPOGRAPHIQUE |
| `voyager` | voyager | DARK, LIGHT, VINTAGE |
| `toner` | toner-v2 | BACKGROUND, LITE, LINES |
| `landscape` | landscape | DARK, VIVID |
| `aquarelle` | aquarelle | DARK, VIVID |
| `ocean` | ocean | — |
| `satellite` | satellite | — |
| `hybrid` | hybrid | — |
| `openstreetmap` | openstreetmap | — |

::prose-show-case
:dnax-demo-map{demo="styles"}

#code

```vue
<script setup lang="ts">
import { ref } from "vue"

const styles = ["streets", "basic", "dataviz", "outdoor", "satellite"]
const mapStyle = ref("streets")
</script>

<template>
  <q-btn-group>
    <q-btn
      v-for="name in styles"
      :key="name"
      flat
      no-caps
      :color="mapStyle === name ? 'primary' : ''"
      :label="name"
      @click="mapStyle = name"
    />
  </q-btn-group>

  <q-map :map-style="mapStyle" center="[2.35, 48.85]" :zoom="12" />
</template>
```
::

`map-style` is reactive: changing it calls the SDK's `setStyle`, the markers and popups —
which are DOM elements — stay in place.

The **dark variant** is picked automatically when the app switches to dark mode (the
`.dark` class on `<html>`, like every other component); `:dark="true"` / `:dark="false"`
forces one. A variant that has no `.DARK` keeps its default look.

Any other style — a variant, a custom style from the style editor — is passed through as
an ID or a URL:

```vue
<q-map map-style="streets-v2-pastel" />
<q-map map-style="c912ffc8-2360-487a-973b-59d037fb15b8" />
<q-map map-style="https://api.maptiler.com/maps/<id>/style.json" />
```

## 3D terrain & globe projection

Both are **reactive** props: they call the SDK's methods (`enableTerrain`,
`setProjection`) — no map reload, no losing the view.

::prose-show-case
:dnax-demo-map{demo="terrain"}

#code

```vue
<q-map map-style="outdoor" terrain projection="globe" :center="[6.8649, 45.8327]" :zoom="11.5" />
```
::

Every other MapTiler option goes through `options` (merged last into the SDK's `Map`
constructor): terrain exaggeration, globe halo and space background, label language,
projection control…

```vue
<q-map
  map-style="outdoor"
  terrain
  projection="globe"
  :options="{
    terrainExaggeration: 1.5,
    language: 'fr',
    halo: true,
    projectionControl: true,
  }"
/>
```

## Controls

| Prop | SDK option | Default corner |
| --- | --- | --- |
| `navigation` | `navigationControl` | `top-right` (zoom, compass, tilt) |
| `geolocate` | `geolocateControl` | `top-right` (browser geolocation button) |
| `scale` | `scaleControl` | `bottom-right` (hidden by default) |
| `fullscreen` | `fullscreenControl` | `top-right` (hidden by default) |

Each accepts `true` (the SDK's default corner), `false`, or `top-left` / `top-right` /
`bottom-left` / `bottom-right`:

```vue
<q-map :navigation="false" geolocate scale="bottom-left" fullscreen="top-left" />
```

Two names are close, keep them apart: the `geolocate` **prop** is the locate **button**,
while the SDK's IP-geolocation **strategy** is the `geolocate` **option** —
`<q-map :options="{ geolocate: 'POINT' }" />` (centres the map on the visitor's country
with `"COUNTRY"`; it is ignored as soon as `center` is set).

`terrainControl`, `projectionControl`, the custom controls (`customControls`), the logo…
are all reachable through `options`.

## The MapTiler client APIs

Beyond the map, the SDK wraps the MapTiler services (client-side only): `geocoding`,
`staticMaps`, `elevation`, `coordinates`, `data`, `math`, plus `gpx`/`kml` conversion and
`helpers.takeScreenshot(map)`. The API key set on a map is propagated to the SDK's
`config`, so they work as soon as one `<q-map>` has mounted:

```ts
import { geocoding, helpers } from "@maptiler/sdk"

const { features } = await geocoding.forward("Paris")
const blob = await helpers.takeScreenshot(map.value.map)   // instance exposée par q-map
```

For a screenshot, note that DOM markers and popups are **not** part of the rendering
context — they are absent from the image.
