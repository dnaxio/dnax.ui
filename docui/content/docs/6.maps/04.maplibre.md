`provider="maplibre"` renders the map with
**[MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/)** alone — the open-source
engine the MapTiler SDK is built on. No key, no account: the **style is the data source**,
so you point it at whatever tiles you have.

::prose-show-case
:dnax-demo-map{demo="maplibre"}

#code

```vue
<script setup lang="ts">
const marks = [{ type: "marker", position: [2.3522, 48.8566], label: "Paris", color: "primary" }]
</script>

<template>
  <!-- globe + style de démonstration MapLibre : rien à installer, aucune clé -->
  <q-map provider="maplibre" projection="globe" :center="[10, 35]" :zoom="1.6" :marks="marks" />
</template>
```
::

## Styles

`map-style` takes a short name, an URL or a style object:

| `map-style` | Style |
| --- | --- |
| *(default)*, `demotiles` | the [MapLibre demo style](https://demotiles.maplibre.org/style.json) — the whole world, free |
| `openstreetmap` | the OSM raster style built by `osmStyle()`, `tiles` / `attribution` included |
| an URL | any style: your own server, a third-party style, a MapTiler style URL… |
| an object | a complete style spec (or `:options="{ style }"`) |

```vue
<q-map provider="maplibre" map-style="openstreetmap" center="[2.35, 48.85]" :zoom="12" />

<q-map
  provider="maplibre"
  map-style="https://api.maptiler.com/maps/outdoor-v2/style.json?key=YOUR_KEY"
/>
```

A short name that is not in the table (`"topo"`, `"satellite"`…) falls back to the demo
style **and warns in the console**: MapLibre has no shared style catalogue, only URLs —
names belong to a provider. (`streets`, the design system default, is one of them and
maps to the demo style without warning.)

## Globe projection

`projection="globe"` works here too (MapLibre 5) — the demo above is one. Like with
MapTiler it is applied **after** the style loads, then follows the prop, so switching back
to `mercator` does not reload the map.

## Terrain

MapLibre ships no terrain tiles: it needs a **DEM source declared by the style**. Pass it
through `options` — the `terrain` prop has nothing to enable on its own:

```vue
<q-map provider="maplibre" :options="{ terrain: { source: 'mon-dem', exaggeration: 1.5 } }" />
```

## Controls

MapLibre mounts **no control by itself**; `<q-map>` adds the same ones as the other
providers, from the same props — `navigation` (zoom / compass / tilt, on by default),
`geolocate` (on by default), `scale` and `fullscreen` (off by default). `false` removes
one, a corner name moves it:

```vue
<q-map provider="maplibre" :scale="true" navigation="bottom-left" :geolocate="false" />
```

## The exposed instance

`@ready` and the exposed `map` hand over the `Map` instance itself: the whole MapLibre API
(sources, layers, filters, expressions, plugins) is at hand.

```vue
<q-map ref="map" provider="maplibre" … />

<script setup lang="ts">
const map = ref()

// après l'événement `ready`
map.value.map.addSource("villes", { type: "geojson", data: villes })
map.value.map.addLayer({ id: "points", type: "circle", source: "villes" })
</script>
```

## Compared to the other providers

- vs [MapTiler](/docs/maps/maptiler): the same engine underneath, but without the style
  catalogue, the key and the client APIs (geocoding, static maps, elevation) — you bring
  your own tiles and your own style.
- vs [Leaflet](/docs/maps/leaflet): vector rendering (WebGL), a style-driven map, the
  globe projection — heavier, and it requires WebGL.
