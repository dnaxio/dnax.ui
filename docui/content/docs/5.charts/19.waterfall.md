**`{ type: 'waterfall' }`** shows how successive **deltas** build (or erode) a total: revenue →
costs → gross profit. Bars are **floating** (they start where the previous one ended), negatives
are coloured with the `negative` token, and dashed **connectors** link the steps:

::prose-show-case
<dnax-demo-chart demo="waterfall"></dnax-demo-chart>

#code

```vue
<script setup lang="ts">
const cashflow = [
  { step: 'Revenue', delta: 120 },
  { step: 'COGS', delta: -45 },
  { step: 'Payroll', delta: -38 },
  { step: 'Marketing', delta: -17 },
  { step: 'Gross profit', delta: 0, total: true },
]
</script>

<template>
  <q-chart
    title="From revenue to gross profit"
    :height="280"
    :marks="[
      { type: 'waterfall', data: cashflow, x: 'step', y: 'delta', isTotal: 'total', name: 'Cash flow', labels: true },
    ]"
  />
</template>
```

::

| Key | Effect |
| --- | --- |
| `x` / `y` | Step label / signed delta |
| `isTotal` | Channel marking the **total** rows (`true` → the bar starts at zero and reads the running total) |
| `fill` | Colour of the positive deltas |
| `negativeFill` | Colour of the negative deltas (default: the `negative` token) |
| `labels` | Prints the delta (or the total on a total row) |
| `labelFormat` | Format of those labels |

::prose-callout{variant="note"}
A waterfall expects its **own categories**: it draws floating bars mapped to the category axis by
index. Give it a dedicated `<q-chart>` when the other marks do not share exactly the same `x`
values.
::
