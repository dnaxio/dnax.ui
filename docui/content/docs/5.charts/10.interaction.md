A dashboard shows the same data several ways: bars for the volume, a pie for the shares, a
line for the trend, dots for the detail. Reading one of them should move the others — hover a
month, click a slice, and the four charts tell the same story. Give them the same **`group`**
and it works, without a line of glue code:

::prose-show-case
<dnax-demo-chart demo="interaction"></dnax-demo-chart>

#code

```vue
<script setup lang="ts">
import { ref } from "vue"
import type { QChartPick } from "@dnax/ui"

const monthly = [
  { month: "Jan", revenue: 42, cost: 28 },
  { month: "Feb", revenue: 51, cost: 31 },
  { month: "Mar", revenue: 47, cost: 30 },
  { month: "Apr", revenue: 63, cost: 35 },
]

/** The one shared piece of state: what the user last picked */
const picked = ref<QChartPick | null>(null)
</script>

<template>
  <div class="grid">
    <!-- Bar: the volume, filtered on the selection -->
    <q-chart
      :height="200"
      group="revenue"
      :selected="picked"
      :marks="[{ type: 'bar', data: monthly, x: 'month', y: 'revenue', fill: 'chart-1', name: 'Revenue', link: 'month' }]"
      @pick="picked = $event"
    />

    <!-- Pie: the shares — it is the *selector*, so it is not linked -->
    <q-chart
      :height="200"
      group="revenue"
      :selected="picked"
      :legend="{ position: 'right', offset: 36, action: 'select' }"
      :marks="[
        { type: 'pie', data: monthly, x: 'month', y: 'revenue', radius: '48%', labels: 'percent', name: 'Revenue' },
      ]"
      @pick="picked = $event"
    />

    <!-- Line: the trend -->
    <q-chart
      :height="200"
      group="revenue"
      :selected="picked"
      :marks="[{ type: 'line', data: monthly, x: 'month', y: 'cost', stroke: 'primary', name: 'Cost', link: 'month' }]"
      @pick="picked = $event"
    />

    <!-- Dot: the detail -->
    <q-chart
      :height="200"
      group="revenue"
      :selected="picked"
      :marks="[{ type: 'dot', data: monthly, x: 'month', y: 'revenue', fill: 'chart-2', r: 5, name: 'Revenue', link: 'month' }]"
      @pick="picked = $event"
    />
  </div>
</template>
```

::

Click a bar, or the legend entry *Jan* of the pie: the three linked charts shrink to January.
Hover a category and the tooltips line up. Four mark types, four props.

## The mental model

Four props, two roles. Two of them **speak**, two of them **listen** — everything else is
plumbing:

| Level | What moves between the charts | Props |
| --- | --- | --- |
| **Hover** | Axis pointer and tooltip — each chart shows *its own* value for the hovered category | `group` (one name for all) |
| **Highlight** | The picked element is emphasised in every chart, in every series carrying that name | `@pick` → `selected` |
| **Filter** | The linked marks keep only the rows that match the selection | `@pick` → `selected` + `link` on the mark |

The three are independent: use `group` alone for a classic linked-tooltip dashboard, add
`selected` for the emphasis, add `link` where the charts must actually filter.

### Events and props — who owns what

`@pick` is an **event** (it happened), `selected` is a **prop** (it is true now). The chart keeps
**no selection of its own**: it renders what `selected` says and nothing else. That is why the two
travel together in every example — and why each is useful on its own:

| | `@pick` / `@unpick` | `selected` |
| --- | --- | --- |
| Nature | Event, emitted **by** the chart | Prop, given **to** the chart |
| Direction | chart → your code | your code → chart |
| Lifetime | One instant (the click) | Until you change it |
| Who decides | The user | Your application — a click, a table row, a URL… |
| If you ignore it | Nothing happens on click, and `selected` can still be driven from elsewhere | The click is emitted, but nothing is highlighted or filtered |

In short: **`@pick` is the question, `selected` is the answer.** A chart bound to `@pick` only is
a reporter (log it, route it, open a panel); a chart bound to `selected` only is a follower
(a filter, a URL, a table selects for it).

## Install it, step by step

1. **Give every chart the same group** — that is the hover and the tooltip:

   ```vue
   <q-chart group="revenue" :marks="[…]" />
   <q-chart group="revenue" :marks="[…]" />
   ```

2. **Name your marks** (`name`) — a named mark gets a legend entry, and the legend is how the
   user picks a member of a series. Without `name` there is nothing to select in a pie.

3. **Keep the pick in your own state** and hand it back to every chart:

   ```ts
   const picked = ref<QChartPick | null>(null)
   ```

   ```vue
   <q-chart group="revenue" :selected="picked" @pick="picked = $event" :marks="[…]" />
   ```

4. **Declare the join** on the marks that must filter (`link: 'month'`) — and leave it off on
   the chart that plays the selector (the pie keeps all its slices).

That is the whole API. Each section below takes one prop and shows what it does.

## `group` — the hover

```vue
<q-chart group="revenue" :marks="[…]" />
```

Charts sharing a `group` are connected: the **shareable interactions** of the chart you touch
are replayed on the other charts of the group:

| Replayed on the group | |
| --- | --- |
| Axis pointer, tooltip | Hovering a category (or a point) lines the others up; each chart reads **its own** value — `Feb 51` in the bar chart, `Feb 31` in the line |
| `dataZoom`, `visualMap` | Panning, zooming and interval selections stay aligned (when you add those components) |

::prose-callout{variant="warning"}
Two things are **not** replayed, by design: the **emphasis** (`highlight` / `downplay`) and the
**legend** — they are local view states. Synchronising them is what `selected` and
`legend.action` are for.
::

`group` carries the interaction only, never the data: each chart keeps its own `marks`, axes
and options. Charts are connected while they are mounted; unmounting one leaves the group
alone. Use one group per dashboard section (`"revenue"`, `"stores"`) so two independent groups
on the same page never talk to each other. Charts of a group should share their category axis
(`x`), otherwise the axis pointer has nothing to line up.

::prose-show-case
<dnax-demo-chart demo="link-hover"></dnax-demo-chart>

```vue
<!-- Two charts, one group name — and nothing else -->
<q-chart group="hover" :marks="[{ type: 'bar',  data: monthly, x: 'month', y: 'revenue' }]" />
<q-chart group="hover" :marks="[{ type: 'line', data: monthly, x: 'month', y: 'cost' }]" />
```

## `@pick` — what was clicked

Every click on an element — bar, point, slice, cell, label — emits a normalised payload:

```vue
<q-chart :marks="[…]" @pick="onPick" />
```

```ts
const onPick = (pick: QChartPick) => {
  console.log(pick) // { name: 'Feb', value: 51, markName: 'Revenue', markIndex: 0, … }
}
```

| Key | Value |
| --- | --- |
| `name` | The datum name — the category on a `band` axis (`Feb`), or the `name` of a slice / cell |
| `value` | Its value (a number, or `[x, y]` on a cartesian mark) |
| `markName` / `markIndex` / `markType` | Which **mark** was clicked — its `name`, its index in `marks`, its `type` (`bar`, `pie`…) |
| `dataIndex` | Position of the datum inside that mark |
| `origin` | `mark` for a chart element, `legend` for a legend entry |
| `data` | The **raw datum** — *your* row, restored by the component; what `link.foreignField` joins on |

The renderer only hands over its own shape (`{ value: ['Feb', 51] }`); the component looks the
row back up in your `marks` by its position, so `data` is the object **you** passed —
`{ month: 'Feb', revenue: 51 }` — on an element click as well as on a legend click. That is what
makes `link.foreignField` work the same either way.

The payload is deliberately **plain and comparable**: absent keys are omitted, so
`pick.name === 'Feb'` is enough to drive a router, a table, a filter or a form. Nothing is
interpreted for you — the click is data, not behaviour.

A click is also a **toggle**: clicking the element that is **already selected** (the same bar, the
same slice, the same month in another mark) does not re-select it — it **clears the selection**,
exactly like a re-click on a legend entry. `@pick` receives `null`, `@unpick` receives the
element that was dropped, and the linked charts go back to their full data.

A click that hits no datum (the empty area of the plot, an axis) emits **nothing**: only a data
element is a selection.

## `selected` — the shared state

`@pick` says what the user clicked; `selected` says what is **currently selected**, whoever
decided it: a chart, a table row, a query parameter.

### What `selected` accepts

Any `QChartPick` — the very payload `@pick` hands you. Only `name` is required to highlight and
to join; the rest is the element's **identity**, carried along so your application knows exactly
what is selected, whatever the origin:

| Field | Used for |
| --- | --- |
| `name` | The highlight (every series carrying it) **and** the default join key |
| `data` | The `link.foreignField` join — the raw row |
| `markName` / `markIndex` / `markType` | Which mark the selection comes from (your logic, analytics) |
| `dataIndex` | Its position inside that mark |
| `origin` | `mark` (an element) or `legend` (a legend entry) |
| `value` | The element's value |

A click on an element and a click on a legend entry produce the **same shape** — only `origin`
differs, and the legend one is reconstructed from the entry name:

```ts
// click on a bar
{ name: 'Feb', value: 51, markName: 'Revenue', markIndex: 0, markType: 'bar', dataIndex: 1, origin: 'mark',   data: { month: 'Feb', … } }
// click on the pie's legend entry “Jan”
{ name: 'Jan', value: 42, markName: 'Revenue', markIndex: 1, markType: 'pie', dataIndex: 0, origin: 'legend', data: { month: 'Jan', … } }
```

### What it does

Hand that pick back to every chart — no need to copy fields out of it:

```vue
<script setup lang="ts">
// `picked` **is** the identity: name, value, markName, markIndex, markType, dataIndex, origin, data
const picked = ref<QChartPick | null>(null)
</script>

<template>
  <q-chart group="revenue" :selected="picked" @pick="picked = $event" :marks="[…] " />
</template>
```

| `selected` | Effect |
| --- | --- |
| `{ name: 'Feb' }` — or a whole `QChartPick` | Every series carrying `Feb` is emphasised, in every chart |
| `{ markIndex: 0, dataIndex: 2 }` (no name) | The precise element is emphasised |
| `null` | The selection is cleared |

A **minimal** selection is enough: `{ name: 'Feb' }` drives everything, the identity fields are
simply absent. And because it is a prop, a chart driven by `selected` follows another one even
**outside** its group — link a chart with a table, a list, or a URL parameter:

```vue
<script setup lang="ts">
const month = new URLSearchParams(location.search).get("month") // 'Feb'
const picked = ref<QChartPick | null>(month ? { name: month } : null)
</script>
```

## `link` — cross-filtering

Hovering links charts; **clicking can filter them**. A mark declares how its own rows join the
shared selection, and the chart keeps only the rows that match:

```ts
// The pie is the selector — it keeps all its slices…
{ type: 'pie',  data: monthly, x: 'month', y: 'revenue', name: 'Revenue' }

// …the others only show the selected month
{ type: 'bar',  data: monthly, x: 'month', y: 'revenue', link: 'month' }
{ type: 'line', data: monthly, x: 'month', y: 'cost',    link: 'month' }
{ type: 'dot',  data: monthly, x: 'month', y: 'revenue', link: 'month' }
```

`link` is the **local field** of the mark: the join key comes from the selection (the datum
that was clicked, or whatever `selected` holds). A mark **without** `link` is never filtered —
that is how the pie stays whole while the others react. `link` is declared **per mark**, so a
chart can filter one layer and leave another intact.

### Two ways to react: `filter` or `dim`

By default a linked mark **drops** the rows that do not match: the chart rescales to the
selection. Sometimes you want the opposite — keep everything and **grey out** what is not
selected, so the shape, the scale and the other points stay readable.

::prose-callout{variant="note"}
**What `dim` means** — to *dim* is the English verb for "make something less bright". A dimmed
element is still there, just **faded** (a lower opacity); in other words *estompé*. It is not
hidden, and not darkened either.
::

| `link-mode` | The rows that do not match | Read as |
| --- | --- | --- |
| `filter` *(default)* | Removed — the axis rescales to the selection | "what happened in February?" |
| `dim` | Kept, drawn at `dim-opacity` (default `0.25`) | "February, **in context**" |

The two demos below are the same charts, the same click — only the mode changes. The `dim` one
also carries a **`table`** mark: a table is a linked mark like any other, so its rows stay on
screen too and only the others fade — the data underneath the chart, at a glance.

**`filter`** (the default) — clicking a month removes the others and the axis rescales:

```vue
  :selected="picked"
  :marks="[{ type: 'bar', data: monthly, x: 'month', y: 'revenue', link: 'month' }]"

```

**`dim`** — the same click, but the others stay on screen at a lower opacity:

::prose-show-case

```vue

  link-mode="dim"
  dim-opacity="0.25"
  :selected="picked"
  :marks="[{ type: 'bar', data: monthly, x: 'month', y: 'revenue', link: 'month' }]"
  @pick="picked = $event"
/>
```

::

In `dim` mode the selected element is what comes back to full contrast. The component drives the
renderer's **`select`** state instead of the highlight, so the emphasis and the dimming are the
same mechanism — and an element with no selection at all is **never** dimmed: at rest, every
chart is at full contrast.

::prose-callout{variant="note"}
`link-mode` is a **chart** setting (it is how the chart draws its marks), while `link` is per
**mark** (it is what makes a mark react at all). A mark without `link` is never filtered nor
dimmed, whatever the mode.
::

### Joining fields that are not named the same

`link` also takes an object, Mongo style: `localField` is read in *this* mark's rows,
`foreignField` in the datum of the selection (`pick.data`), falling back to the pick itself,
then to its `name`.

```ts
// This chart groups by channel; the chart that drives it groups by month
{ type: 'bar', data: byChannel, x: 'label', y: 'revenue', link: { localField: 'label', foreignField: 'month' } }
```

| `link` | Join key |
| --- | --- |
| `'month'` | `row.month === selected.data.month ?? selected.month ?? selected.name` |
| `{ localField: 'label', foreignField: 'month' }` | `row.label === selected.data.month` |

::prose-callout{variant="note"}
Two guard rails keep a mis-spelled key from emptying a chart: with **no selection** every mark
shows everything, and when **no row carries** the `localField` the mark keeps its data (the
join is simply ignored).
::

Two charts holding the same values under two different names — `month` in one, `label` in the
other:

### One axis for all the marks

The axis categories are the **union of the marks** of the chart: a single linked mark among
unlinked ones keeps its full axis (the linked one just has one bar). Link **every** mark and
the chart rescales to the selection — that is what the demo above does.

## The legend as a selector

A legend click does not emit a chart click: it turns the series (or the slice) off instead. Ask for `action: 'select'` and the legend becomes a **selector** — the click emits
`@pick` with the entry name, the series stay visible, and clicking the same entry again clears
the selection:

```vue
<q-chart
  group="revenue"
  :legend="{ position: 'right', action: 'select' }"
  :selected="picked"
  @pick="picked = $event"
  :marks="[pie]"
/>
```

| `legend.action` | A click on a legend entry |
| --- | --- |
| `toggle` *(default)* | Hides the series / the slice — emits nothing |
| `select` | Emits `@pick` with the entry name; the entry itself **stays visible** |

In `select` mode, a click is one of three cases — and a re-click on the current name **is** the
unselect, there is no second event to listen to:

| You click… | `@pick` receives | What the linked charts do |
| --- | --- | --- |
| an entry that is not selected (`Jan`) | `{ name: 'Jan', origin: 'legend', markName, markIndex, markType, dataIndex, data, value }` | they filter on January |
| another entry, while `Jan` is selected (`Feb`) | `{ name: 'Feb', origin: 'legend', data }` | they **switch** to February |
| the entry that **is** selected (`Jan` again) | `null` — and `@unpick` with `{ name: 'Jan' }` | the selection is cleared, everything comes back |

A deselection is signalled **twice**, on purpose: `@pick` carries the **state** (`null`), and
`@unpick` carries the **action** — the element that was dropped (a re-click on the selected
element, or on the selected legend entry), so you can log it, push it to
analytics or clear a related panel:

```vue
<q-chart :selected="picked" @pick="picked = $event" @unpick="onUnpick" :marks="[pie]" />
```

```ts
const onUnpick = (dropped: QChartPick) => {
  console.log('deselected', dropped.name) // { name: 'Jan', origin: 'legend', data: { … } }
}
```

`@unpick` fires **only** on a user deselection. Clearing from your code (`picked = null`) touches
`@pick` not at all — no echo, no loop.

The clicked entry is always restored (the slice stays in the pie) — the emphasis and the
filtering are driven by `selected`, never by hiding a series.

The demo above shows **both sides**: click `Jan` and the bar shrinks to January; re-click it, or
press **Clear**, and every month comes back — "no longer selected" is simply `picked = null`.

The smallest cross-filter: a pie whose legend drives a single bar. The pie is **not** linked, so
it keeps every slice; the bar filters, and the linked chart is the only one that moves.

## Recipes

**Four views, one selection.** The demo above is the pattern: a bar chart for the volume, a pie
for the shares, a line for the trend, dots for the detail — same `group`, same `picked`, and
`link: 'month'` on the three that must shrink.

**A chart driving a table.** Keep the pick in your own state and filter on `pick.name`:

```ts
const rows = computed(() => (picked.value ? data.filter((d) => d.month === picked.value!.name) : data))
```

**A filter driving the charts.** The reverse: a select, a tab or the URL sets `picked`, and
every chart reflects it.

**A filter driving the charts — without any chart click.** The selection can come from
anywhere: a `<select>`, tabs, the URL. Here a menu drives both charts, and **All months** puts
them back to the unselected state:

::prose-show-case
<dnax-demo-chart demo="link-app"></dnax-demo-chart>

#code

```vue
<script setup lang="ts">
const month = ref("") // '' = all months
</script>

<template>
  <select v-model="month">
    <option value="">All months</option>
    <option v-for="m in months" :key="m" :value="m">{{ m }}</option>
  </select>

  <!-- A plain object is enough: `selected` only needs a name -->
  <q-chart :selected="month ? { name: month } : null" :marks="[barLinked]" />
  <q-chart :selected="month ? { name: month } : null" :marks="[dotsLinked]" />
</template>
```

::

**Clearing the selection.** "No longer selected" is not a special case: set the state to
`null` and every chart returns to its full data (a re-click on the selected legend entry emits
exactly that).

```vue
<template>
  <button @click="picked = null">Clear</button>
  <q-chart :selected="picked" @pick="picked = $event" :marks="[linkedBar]" />
</template>
```

**Clicking in the empty area.** A click in the void triggers no `@pick` (there is no element).
Use the exposed instance to clear the selection:

```vue
<q-chart ref="c" :marks="[…]" />
```

```ts
c.value.chart.getZr().on("click", (event: any) => {
  if (!event.target) picked.value = null
})
```

## When it doesn't work

| Symptom | Cause | Fix |
| --- | --- | --- |
| Hovering does nothing | Charts have different (or no) `group` | Give them the **same** `group` string |
| The tooltip follows, but the clicked element stays dull | `selected` is not bound | `:selected="picked"` on the chart, `@pick="picked = $event"` |
| Clicking the legend hides the slice instead of selecting | `legend.action` is missing | `:legend="{ action: 'select' }"` |
| Clicking works, nothing filters | The mark has no `link` | Add `link: 'month'` (the field shared with the selection) |
| Only one chart filters | The other charts have no `link` | Link **every** mark of a chart for its axis to shrink |
| Everything empties on click | The selection key does not exist in `rows` | Check the field name — the join is ignored when the field is absent, but a *wrong value* filters everything out |
| The highlight targets the wrong elements | `name` collides between series | Give the marks distinct `name`s, or drive the selection with `picked.name` values you control |

## What the link does not do

- **No shared data**: each chart builds its own option from its own `marks` — the link replays
  interactions and `link` filters rows, it never moves data between charts.
- **No range brush**: selecting a *range* (drag) to filter is not built in — that still needs
  your own state + `selected` (or the `options` escape hatch with a custom `brush` handler).
- **No layout coupling**: heights, axes and legends stay per chart; synchronise them yourself
  if you want pixel-identical panels.
