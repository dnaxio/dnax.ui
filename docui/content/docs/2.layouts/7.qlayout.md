**`<q-layout>`** turns a page into an application shell: a 3×3 matrix whose rows are
the header, the middle band and the footer, and whose columns are the left drawer, the
content and the right drawer. Children **place themselves** in that matrix — no
wrapper, no markup order to respect:

```vue
<q-layout view="hHh LpR fFf">
  <q-header>…</q-header>
  <q-sidebar side="left" show-if-above>…</q-sidebar>
  <q-page>…</q-page>
  <!-- the content -->
  <q-footer>…</q-footer>
</q-layout>
```

## The `view` string

`view` is the matrix itself: three groups of three characters — the **header row**,
the **middle row** and the **footer row**.

| Letter | Zone |
| --- | --- |
| `l` | left drawer (`<q-sidebar side="left">`) |
| `h` | header (`<q-header>`) |
| `r` | right drawer (`<q-sidebar side="right">`) |
| `f` | footer (`<q-footer>`) |
| `p` | page — the content |
| `.` | empty cell |

**The letter case is the whole point**: an uppercase letter means that zone **keeps its
place** while the page scrolls (it gets `position: sticky`), a lowercase one means it
**flows with the page**. A zone spanning several cells must form a full rectangle.

| `view` | Result |
| --- | --- |
| `hHh LpR fFf` | header and footer full width, both drawers between them — everything stays in place (the default) |
| `hhr lpR ffR` | the right drawer spans all three rows: it runs the full height, beside the header and the footer |
| `lhh LpR fff` | the left drawer occupies the header row too: it starts **above** the header |
| `hHh .p. fFf` | no drawer at all |

## Basic

The default shell: a `sticky` header, a `sticky` drawer on the left, a `sticky` footer
and the page scrolling under them. The framed box below is a **containerized** layout
(`container` + an explicit height) — handy for demos, and the only mode where the
layout scrolls on its own instead of the document.

::prose-show-case
:dnax-demo-layout{demo="basic"}

#code

```vue
<script setup lang="ts">
const menus = ["Dashboard", "Projects", "Analytics"]
</script>

<template>
  <q-layout view="hHh LpR fFf" container class="shell">
    <q-header bordered>
      <q-toolbar><b>Console</b><q-space /><q-btn flat round dense icon="lucide:search" /></q-toolbar>
    </q-header>

    <q-sidebar side="left" show-if-above>
      <q-sidebar-content>
        <q-sidebar-menu>
          <q-sidebar-menu-item v-for="label in menus" :key="label">
            <q-sidebar-menu-button :label="label" />
          </q-sidebar-menu-item>
        </q-sidebar-menu>
      </q-sidebar-content>
    </q-sidebar>

    <q-page>…</q-page>

    <q-footer bordered>
      <q-toolbar>Dnax UI · console</q-toolbar>
    </q-footer>
  </q-layout>
</template>
```
::

## Drawer above the header

Put the drawer in the header row as well (`lhh`) and it starts higher than the header.
Its sticky offset follows that: only the bars it does *not* span are subtracted, so it
still fills the visible height exactly.

::prose-show-case
:dnax-demo-layout{demo="above"}

#code

```vue
<q-layout view="lhh LpR fff">
  <q-header>…</q-header>
  <q-sidebar side="left" show-if-above>…</q-sidebar>
  <q-page>…</q-page>
  <q-footer>…</q-footer>
</q-layout>
```
::

## Flowing letters

Lowercase letters move that zone back into the page flow: here the header and the
drawer scroll away with the content, and only what you asked to keep (uppercase) stays
put.

::prose-show-case
:dnax-demo-layout{demo="flowing"}

#code

```vue
<q-layout view="hHh lpr fff">
  <q-header>…</q-header>
  <q-sidebar side="left" show-if-above>…</q-sidebar>
  <q-page>…</q-page>
  <q-footer>…</q-footer>
</q-layout>
```
::

## Good to know

- **Direct children only.** The zones are the direct children of `<q-layout>`; the
  matrix is a CSS grid and each zone is a grid cell.
- **One content child.** Everything that is not a header, a footer or a sidebar lands
  in the page cell. Two siblings landing there would overlap (grid items share the
  cell), so wrap them in a single element — usually `<q-page>`.
- **Scroll stays on the document** (except in `container` mode, which scrolls its own
  box). That is why a `sticky` bar is enough here — no `fixed` position, no offset
  compensation: a `q-header` marked `sticky` is **clipped to its own cell**, so it can
  never cover the drawer next to it.
- **No `sticky` prop needed.** `q-header`, `q-footer` and `q-sidebar` read the case of
  their letter inside a `<q-layout>`: `H` implies `sticky` on the header, `F` on the
  footer, `L`/`R` on the drawer. The props remain available outside a layout.
- **`F` and `f` look the same.** The footer row is the last one, so the footer ends up
  at the end of the page either way; `H`/`h` and `L`/`R`/`l`/`r` are where the case
  really shows.
- **Below the drawer `breakpoint`** (1023px by default, or the width of the container)
  a `q-sidebar` becomes an offcanvas panel: it leaves the grid, overlays the content
  with a backdrop, and its `v-model` takes over — hide your ☰ button above the
  breakpoint, since it does nothing visible there.
- **Safe-area insets** are already applied by the bars and by the page, sticky included.
