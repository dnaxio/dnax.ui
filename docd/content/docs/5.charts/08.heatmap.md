**`{ type: 'heatmap' }`** draws **one cell per row**: `x` is the column, `y` the row — both
are **category axes** — and `fill` is the **value** of the cell, mapped to a colour scale
(just like the `fill` of a Plot rectangle):

::prose-show-case
<dnax-demo-chart demo="heatmap"></dnax-demo-chart>

#code

```vue
<script setup lang="ts">
const temps = [
  { day: "Mon", hour: "9h", temp: 12 },
  { day: "Mon", hour: "13h", temp: 21 },
  { day: "Mon", hour: "17h", temp: 19 },
  { day: "Tue", hour: "9h", temp: 8 },
  { day: "Tue", hour: "13h", temp: 18 },
  { day: "Tue", hour: "17h", temp: 23 },
  { day: "Wed", hour: "9h", temp: 14 },
  { day: "Wed", hour: "13h", temp: 26 },
  { day: "Wed", hour: "17h", temp: 30 },
  { day: "Thu", hour: "9h", temp: 10 },
  { day: "Thu", hour: "13h", temp: 24 },
  { day: "Thu", hour: "17h", temp: 27 },
]
</script>

<template>
  <q-chart
    title="Temperature by hour"
    :height="260"
    :x="{ label: 'Hour' }"
    :y="{ label: 'Day' }"
    :marks="[
      {
        type: 'heatmap',
        data: temps,
        x: 'hour',
        y: 'day',
        fill: 'temp',
        labels: true,
        name: 'Temperature',
      },
    ]"
  />
</template>
```

::

### A grid of categories — both axes

A heat map uses **both axes as categories**: the columns come from `x`, the rows from `y`,
each in the order the data is read (sort the rows beforehand if the order matters). The
cells are then laid out automatically, one per `(column, row)` pair.

Two consequences:

- the axes of `<q-chart>` are **replaced** by those categories — giving `x` / `y` a
  `label` still works, but a `type` (`linear`, `time`…) is ignored;
- a heat map **cannot share a chart** with a `line`, a `bar` or a `dot`: those need a value
  axis, which a heat map takes over. Use one chart per heat map.

### The value — `fill`

`fill` holds the cell value, as a channel (a field, explicit values, or an accessor):

```ts
{ type: 'heatmap', data: rows, x: 'hour', y: 'day', fill: 'temp' }        // a field
{ type: 'heatmap', data: rows, x: 'hour', y: 'day', fill: (d) => d.c - 273 }  // an accessor
```

Numbers are mapped to a **colour ramp**: the series palette (`colors`, i.e. `--chart-1…6`)
between the smallest and the largest value of the mark. A **colour** instead of a number
(a token like `primary`, or any CSS colour) paints every cell that colour — handy for a
plain grid, or to layer your own encoding on top.

The scale itself is emitted by the mark (`visualMap`): it is drawn under the chart, with the minimum and the maximum on each side. For a custom ramp,
a different position, or a range selector, pass it through the escape hatch — it is merged
**after** the generated one:

```vue
<q-chart
  :marks="[{ type: 'heatmap', data: rows, x: 'hour', y: 'day', fill: 'temp' }]"
  :options="{ visualMap: [{ min: 0, max: 40, inRange: { color: ['#fff', '#c10015'] }, calculable: true }] }"
/>
```

Given a constant colour there is nothing to scale, so the `visualMap` is emitted **hidden**
and the cells keep that colour.

### Labels and tooltips

| Key | Effect |
| --- | --- |
| `labels: true` | Prints the value **inside** each cell. |
| `title` | Per-cell tooltip — a channel, to replace the default. |
| `opacity` | Applies to the whole grid. |
| `name` | Series name (legend entry and tooltip). |

`title` sets the **tooltip** of a cell — a channel of your own (the raw temperature, a
formatted date, a label…). A chart made of a heat map
alone is hovered cell by cell — never as an axis.
