`<q-chart>` is not only for plots. A **`table`** mark shows the same rows as a table — same
`data`, same `link` jointure, same `selected`, same `@pick` — but rendered in **HTML** instead of
on the canvas. Text is selectable, long lists scroll, screen readers read it, and it costs
nothing to draw:

::prose-show-case
<dnax-demo-chart demo="table"></dnax-demo-chart>

#code

```vue
<script setup lang="ts">
import { ref } from "vue"
import type { QChartPick } from "@dnax/ui"

const monthly = [
  { month: "Jan", revenue: 42, cost: 28 },
  { month: "Feb", revenue: 51, cost: 31 },
  { month: "Mar", revenue: 47, cost: 30 },
]

const picked = ref<QChartPick | null>(null)
</script>

<template>
  <!-- The plot: click a bar to pick a month -->
  <q-chart
    :height="200"
    :selected="picked"
    :marks="[{ type: 'bar', data: monthly, x: 'month', y: 'revenue', name: 'Revenue' }]"
    @pick="picked = $event"
  />

  <!-- The table: same rows, same selection, no canvas -->
  <q-chart
    :height="240"
    :selected="picked"
    :marks="[
      {
        type: 'table',
        data: monthly,
        link: 'month',
        columns: [
          { field: 'month', label: 'Month' },
          { field: 'revenue', label: 'Revenue', align: 'end' },
          { field: 'cost', label: 'Cost', align: 'end' },
          { field: 'revenue', label: 'Margin', align: 'end', format: (_v, row) => `${row.revenue - row.cost}` },
        ],
      },
    ]"
    @pick="picked = $event"
  />
</template>
```

::

Click a bar: the table keeps the matching row. Click a row: every linked chart filters on it.
The two views are two marks of the same story.

## Columns

Without `columns`, the columns are **the keys of the rows**, in the order they appear — enough
for a quick dump of any data. Declare them to control the header, the alignment and the
formatting:

```ts
columns: [
  'month',                                                    // the field, as the header
  { field: 'revenue', label: 'Revenue', align: 'end' },        // a label, right-aligned numbers
  { field: 'revenue', label: 'Margin', align: 'end',
    format: (_value, row) => `${row.revenue - row.cost} €` },   // a computed cell
]
```

| Column key | Effect |
| --- | --- |
| `field` | The key read in each row |
| `label` | The header (default: `field`) |
| `align` | `start` *(default)*, `center`, `end` — `end` is what you want for numbers |
| `format` | `(value, row) => string` — formats the displayed cell; the value is left untouched |

## Separators

A table is a grid of cells, and how much of that grid you want to see is a matter of taste — a
dense financial table wants lines, a small dashboard wants air. `separator` settles it **per
mark**:

| Value | What appears |
| --- | --- |
| `horizontal` *(default)* | One line under each row — the header keeps a stronger one |
| `vertical` | Lines between the columns only |
| `grid` | Both, like a spreadsheet |
| `none` | No row lines at all — the header line stays, so the table keeps its shape |

```vue
<q-chart
  :marks="[
    { type: 'table', data: monthly, separator: 'grid',
      columns: [{ field: 'month', label: 'Month' }, { field: 'revenue', label: 'Revenue', align: 'end' }] },
  ]"
/>
```

## A table is a mark like the others

Everything you know about marks applies — that is the whole point of putting the table *in* the
API rather than next to it:

| | |
| --- | --- |
| `data` | The rows, like any mark |
| `link` | Joins the shared selection: the table reacts like a linked chart — rows **filtered** out, or **kept and dimmed** in `link-mode="dim"` (see [Interaction](/docs/charts/interaction)) |
| `selected` | The matching row is highlighted (a left accent bar), whatever picked it |
| `@pick` | A click on a row emits the same payload as a click on an element, with `markType: 'table'`; a second click on the same row clears the selection |
| Row key | The `link` field, or the first column — so a row is designated by **the same `name`** as the other marks |

```ts
// A click on the row "Feb" of the table above
{ name: 'Feb', markType: 'table', markIndex: 1, dataIndex: 1, origin: 'mark', data: { month: 'Feb', … } }
```

That is what makes a table usable as the *driver* as well as the *driven*: click a row and the
bar, the line and the dots follow.

## Two things to know

::prose-callout{variant="note"}
A `table` mark **replaces the plot** of its chart: mixing a `table` with a series mark
(`bar`, `line`…) in the same `<q-chart>` would draw nothing on the canvas. Give the table its own
`<q-chart>` — as in the demo above — and link the two.
::

- **The height is a max**: `height` becomes the table's `max-height`, so a long table scrolls
  inside the chart instead of stretching the page, with a sticky header.
- **The empty state** is a small `No rows` line: a selection that matches nothing (or empty
  `data`) leaves a readable table frame rather than a blank box.
