**`<q-chart>`** takes a **`marks`** array of plain objects: `{ type, data, x, y }`. A
mark is one layer of the chart — nothing to import, it is just data:

::prose-show-case
<dnax-demo-chart demo="line"></dnax-demo-chart>

#code

```vue
<script setup lang="ts">
const monthly = [
  { month: "Jan", revenue: 42, cost: 28 },
  { month: "Feb", revenue: 51, cost: 31 },
  { month: "Mar", revenue: 47, cost: 30 },
  { month: "Apr", revenue: 63, cost: 35 },
]
</script>

<template>
  <q-chart
    title="Revenue vs cost"
    :height="260"
    :marks="[
      { type: 'line', data: monthly, x: 'month', y: 'revenue', stroke: 'primary', name: 'Revenue' },
      { type: 'line', data: monthly, x: 'month', y: 'cost', stroke: 'chart-2', name: 'Cost' },
      { type: 'dot', data: monthly, x: 'month', y: 'revenue', fill: 'primary', r: 3 },
    ]"
  />
</template>
```

::

Three marks on the same data give the “line + dots” look. `name` feeds the legend and
`stroke` / `fill` take a **token** or any CSS color — token values are read from the host
theme, so the chart follows it (light/dark included).

### Series colors

| Token | Meaning |
| --- | --- |
| `chart-1` … `chart-6` | The **series palette** — used automatically by marks without an explicit color (and by the `z` channel). Comes from the host's `--chart-N` when it defines them. |
| `primary`, `info`, `positive`, `warning`, `negative`, `dark` | Follow the host theme (`--primary`…). |
| `secondary`, `accent` | dnax.ui's Material colors (teal / violet). **Deliberately not** read from the host: in shadcn-style themes `--secondary` / `--accent` are *surfaces* (≈ the background), so a series painted with them would be invisible. |
| anything else | Any CSS color (`#2563eb`, `oklch(…)`, `rgb(…)`). |

### Marks

| `type` | Rendering |
| --- | --- |
| `line` | Line through the points |
| `area` | Line with a filled surface underneath |
| `bar` | Bars |
| `dot` | Points (`r` sets the radius — a channel gives a bubble chart) |
| `text` | Labels at `x` / `y` (`text` is the content) — see [Text](/docs/charts/text) |
| `rule` | Reference line (`{ type: 'rule', y: [0] }`) |

Every mark takes its own `data` (an array of rows, or of plain values). Set
`orientation: 'horizontal'` on a mark to flip the axes — categories then run along
the Y axis; all series marks of a chart must share the same orientation.

### Channels

A channel accepts three forms:

```ts
{ x: "month" }                  // field name, resolved per row
{ x: ["Jan", "Feb"] }           // explicit values (or a constant if a single one)
{ x: (d, i) => d.month }        // accessor function
```

Available channels: `x`, `y`, `fill`, `stroke`, `strokeWidth`,
`opacity`, `r`, `title` (per-point tooltip), `text`, `fontSize`, `dx`, `dy`, **`z`** (one
series — and one legend entry — per value) and `stack`. Axes and formatting go through the
props `x`, `y`, `title`, `height`, `colors`, `legend`, `tooltip`, and `options` merges raw
ECharts options last (escape hatch).
